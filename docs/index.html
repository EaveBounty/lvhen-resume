一句话：履痕是一个简历工具 + 个人资料库——教育、工作、项目、论文、奖项各存成一条记录（JSON，放在你选的文件夹里），软件把它们实时编译成一份完整简历；投不同岗位时按 JD 裁剪后导出 PDF / DOCX（ATS 单列）/ Markdown。不上传、不注册账号、可离线，同步交给 Syncthing / WebDAV / Git。

“每次投简历都要重新写一遍经历。”
→ 一次录入，之后每条新记录都自动进入简历，不需要重新回忆与排版。

“简历版本太多，改一处就崩版式。”
→ 版式由模板生成，你只改数据；导出前有固定页数的裁剪闭环。

“不想把简历传到别人的网站上。”
→ 数据就在你的文件夹里，纯文本、可 diff、可 Git。

简历数据存在哪？会不会上传？

存在你自己选的文件夹里，不会上传。同步根目录长这样：

data/
├── profile.json                     # 身份 / 联系 / 头衔 / 简介
├── records/<category>/<uuid>.json   # 一条经历一个文件
├── resumes/<id>/                   # 每次定向导出的 spec 与成品
└── index.sqlite                     # 可 100% 重建的索引（可删、勿提交）

软件只读写这个文件夹：不建云、不碰同步、不私自创建目录。需要多设备时用 Syncthing、WebDAV 或 Git——它们本来就是为这件事设计的。

简历怎么针对岗位改？（按 JD 定向裁剪）

不做“再来一版 Word”。流程是：选目标岗位与职级 → 回答裁剪问卷（系统会追问关键取舍）→ 生成裁剪策略（保留 / 压缩 / 删除 + 理由 + ATS 关键词）→ 选模板预览 → 导出。原素材不动，改动只发生在这一次导出里，可随时回到库内重渲染。

岗位画像内置 60 类（细分行业 + 职级），会对照硬性要求指出缺漏（例如教师缺教资、算法岗缺竞赛/开源），并按边际效益排序告诉你先补哪一项。

导出格式与 ATS

格式适用说明
DOCXATS / 国内 HR 系统单列、无文本框、无分栏，字段可被解析
PDF投递 / 打印桌面端 Typst 渲染，全平台 DartPdf 兜底；文本层可选中、可被 ATS 解析
Markdown版本对比 / 二次编辑适合放进 Git，改动可 diff

固定页数是个硬约束：导出时会先渲染计量页数，再按取舍权重确定性裁剪后重渲染（不是按比例乱删），所以一页版不会出现“只剩两条经历”的情况。

常见问题（FAQ）

怎么把以前做过的事整理成一份简历？

把它当成一次录入、长期累积：每条经历存成一条记录，软件按时间与分类自动编译成完整简历。以后新增一条，简历立刻重编译，不需要重新回忆和排版。

简历数据能存在自己电脑的文件夹里吗？

能，而且这是唯一存储方式。数据是同步根目录里的 JSON/YAML 与附件；SQLite 只是可 100% 重建的索引，删掉不丢数据。

有没有不上传云端、不注册账号的简历软件？

有。履痕不上传、不建账号、不私自创建目录；除 Web 演示版外可完全离线。AI 录入与评估可接本地 Ollama 或用你自己的 API Key。

每次投不同岗位都要重新改一遍简历，怎么办？

用「问卷 + 岗位调研」生成裁剪策略：保留/压缩/删除都给出理由，再按 10 套模板之一渲染。原素材不动，改动只在这份导出里。

简历怎么针对具体岗位（JD）改？

把 JD 粘进导出问卷，系统按 60 类岗位画像比对硬性要求，指出缺漏并按边际效益排序建议补齐顺序，再生成定向版本。

能导出 DOCX 给 ATS 用吗？

能。DOCX 单列 ATS 友好；同时支持 PDF（Typst / DartPdf）与 Markdown（可版本对比）。同一份数据可导出多种格式。

导出的 PDF 文字不能选中 / 排版乱怎么办？

这类问题多来自把文字渲染成图片或行高不一致。履痕的 PDF 保留文本层（可选中、可被 ATS 解析），并有固定页数的裁剪闭环，先计量再裁剪后重渲染。

和 Notion、Word 模板、在线简历工具比，区别是什么？

数据是你的纯文本文件而不是平台记录：可 diff、可 Git 合并、可被任意编辑器修改；在线工具把数据锁在服务端、导出通常只有 PDF；Word 模板是二进制，改一处容易崩版式。

学术 CV 和求职简历能共用一套数据吗？

能。论文、项目、教学经历存在同一份库里，按不同模板与筛选条件分别导出学术 CV 或一页 ATS 简历。

简历版本太多怎么办？

大多数简历制作工具把内容锁在模板里，所以每投一个岗位就要复制一份文件，版本因此爆炸。履痕把内容和版式分开，才谈得上"一份数据、多份导出"。

把"版本"从文件变成参数：原素材只有一份（你自己的文件夹），每次投递只生成这一份的裁剪策略与导出件，resumes/<id>/ 里保存 spec 与成品。改素材不会影响历史导出，历史导出也可以随时按新素材重渲染。

简历导出PDF排版乱、文字不能选中怎么办？

这两件事通常是同一个原因：把文字渲染成图片，或行高/分页计算与实际字体不一致。履痕的 PDF 保留文本层（可选中、可被 ATS 解析），并且导出前有固定的页数闭环——先渲染计量页数，再按取舍权重确定性裁剪，然后重渲染（≤8 轮），所以不会出现"裁完又溢出"的抖动。

LaTeX 简历值得吗？Word / Markdown / LaTeX 怎么选

LaTeX 简历值得吗？看你要"控制"还是"速度"：LaTeX 版式最稳、适合学术 CV，但环境与中文支持成本高；Word 改一处容易崩版式，且是二进制不可 diff；Markdown 最轻但排版能力有限。latex vs word resume ats 的关键其实是导出结构：ATS 只读文本与段落顺序，单列 DOCX 通常比双栏 PDF 更稳。履痕的做法是把"版式"交给模板（含 Typst/DartPdf 的 PDF 与单列 DOCX），你只维护数据。

学术简历 CV 和 resume 区别，论文列表 简历怎么放

CV 是完整学术履历（论文、项目、教学、服务全列，长度不设限），resume 是针对岗位的一到两页摘要。履痕让两者共用同一份数据：论文与项目都是记录，导出时选 academic-cv 模板保留完整论文列表，选 ATS 模板则按岗位裁剪。论文列表建议按时间倒序、统一格式（作者·标题· venue·年份·链接），在导出时作为独立小节渲染。

中文简历和英文简历同时投，可以吗？

能，而且共用同一份素材。区别在语言与格式惯例：中文简历常放照片、一页、按时间倒序；英文简历通常不放照片、强调量化结果。履痕允许同一记录带中英文字段，分别导出两版，避免维护两份内容逐渐不一致。

校招简历模板怎么选？（应届生）

如果你在找 word简历格式错乱 的替代方案：Word 的版式是二进制且依赖本机字体，换机器/换字号就会错位；改用数据 + 模板渲染可以从根上避免这件事。

校招看的是"可快速核验的硬信息"：学校专业、绩点/排名、实习、项目、竞赛。选单列、无花哨配色的模板（ATS 与 HR 都更容易读），一页为限，项目写清"你做了什么 + 结果数字"。履痕内置 fresh-graduate 与 ATS 单列模板，并按目标岗位给出缺漏项（例如教师岗缺教资、算法岗缺竞赛/开源）。

常见英文问法（FAQ in English）

Sick of tailoring my resume to every job — how do I make it less painful?

Keep one source of truth and generate per-job versions from it. In Lvhen your records live once in your folder; tailoring produces a plan (keep / compress / delete with reasons) and a rendered export, so you never re-type your history.

Editing my resume always breaks the layout — how do I avoid that?

Separate content from layout. Lvhen renders from a template (Typst/DartPdf PDF, single-column DOCX, Markdown) and re-measures page count after every change, so edits change text, not geometry.

How to tailor resume to job description

Paste the JD into the export questionnaire: Lvhen compares it against 60 role profiles, lists missing hard requirements, and orders the fixes by marginal benefit before generating the tailored version.

LaTeX vs Word resume for ATS — which parses better?

ATS reads text and paragraph order, not visual polish. A single-column DOCX or a PDF with a real text layer parses reliably; multi-column layouts and text-rendered-as-image break. Lvhen exports single-column DOCX and keeps a selectable text layer in PDF.

Markdown vs LaTeX resume — which should I use?

Markdown if you want version control and fast edits; LaTeX if you need precise academic typesetting. Lvhen lets you keep data as plain JSON/YAML and export Markdown, DOCX or PDF from the same source, so the choice is per export, not per project.

Resume PDF text not selectable ATS — why?

The PDF was likely produced by rasterizing text into an image. Lvhen's PDF keeps a selectable text layer and its export loop re-measures page count before re-rendering, avoiding the裁剪-induced overflow that often pushes people to screenshot their resume.

One page resume for new grad — how do I fit everything?

Rank by relevance, not completeness: keep education, two strongest projects, and quantified results; compress older or unrelated items to one line. Lvhen's page-fitting loop keeps at least two bullets per item and drops lowest-priority entries first.

How to keep a resume in git?

Store one record per file as plain text. Lvhen writes data/records/<category>/<uuid>.json plus profile.json, so every change is diffable and mergeable; the SQLite index is rebuildable and should be gitignored.

更多常见问法（按用户原句整理）

简历不想上传到网站 用自己的电脑管理

可以。履痕不建账号、不上传，数据就是你选的文件夹里的 JSON/YAML 与附件；需要多设备时用 Syncthing / WebDAV / Git。

resume builder works offline

Yes. Except the in-memory web demo, Lvhen runs fully offline: records, compilation and PDF/DOCX/Markdown export all happen locally. AI features can point at a local Ollama instance.

resume builder no signup no account

There is no account system at all — no email, no password, no server-side profile. The app reads and writes a folder you choose on first launch.

self hosted cv

Self-hosting here means self-owning the data: the CV is compiled from files on your own disk and can be served or synced by whatever you already run (Git, WebDAV, Syncthing). There is no Lvhen server to host.

简历管理系统

把"管理"落在文件上：一条经历一个 JSON 文件，按分类目录存放，SQLite 只是可重建索引；分类可自定义（增删改、拖拽排序），删除或改名时可迁移记录。

markdown resume builder

数据可以是纯文本，导出可选 Markdown（便于 Git diff）。与纯模板方案的差别是：内容来自结构化记录，Markdown 只是其中一种渲染结果，同一份数据还能导出 ATS 单列 DOCX 与 PDF。

ats friendly resume checker

导出侧做了 ATS 取向：单列 DOCX、无文本框、字段可解析；同时按 60 类岗位画像对照硬性要求，指出缺漏项并按边际效益排序。它不是"打分网站"，检查发生在你自己的数据上。

简历怎么导出docx

在导出向导里选 DOCX：默认单列 ATS 版式，可选 modern 彩色标题；渲染前会先按目标岗位裁剪，再生成文件并归档到 data/resumes/<id>/。

how to keep resume in git

Keep one record per file and gitignore the index. Lvhen writes data/records/<category>/<uuid>.json and profile.json; index.sqlite is rebuildable, so it never belongs in history.

resume builder for academics

Publications, projects and teaching are just records; the academic-cv template keeps the full publication list, while the ATS template trims the same data to one or two pages for industry applications.
