# 履痕（Lvhen）— 简历工具 + 本地优先的个人资料库

> 把散落的经历整理成一份随时更新的简历；数据存在你自己的文件夹里，不上传、不注册账号、可离线。
> English: [README.md](README.md) ｜ 落地页：<https://eavebounty.github.io/lvhen-resume/>

## 这是给谁用的

- 每次投简历都要把经历**重新写一遍**的人
- 简历版本太多、**改一处就崩版式**的人
- **不想把简历上传到别人网站**、想自己保存成文件的人
- 同时投中文岗与英文岗、需要一套数据出两版的人
- 有论文/项目/教学经历，需要学术 CV 与一页求职简历**共用同一份素材**的人

## 它解决什么问题

个人经历散落在聊天记录、旧简历、云笔记、硬盘目录里。每次求职都要重新拼凑、重复填写、格式不一，而且数据被锁死在某个软件里。

履痕的做法：**一条经历 = 一个 JSON 文件**，放在你亲自选择的同步根目录；软件把这些文件实时编译成一份完整简历。改一条记录，首页简历立刻重算；投不同岗位时，用问卷 + 岗位调研生成裁剪策略，只保留与该岗位相关的内容。

## 数据存在哪？会上传吗？

不会上传。目录结构：

```
data/
├── profile.json                     # 身份 / 联系 / 头衔 / 简介
├── records/<category>/<uuid>.json   # 一条经历一个文件
├── resumes/<id>/                    # 定向导出的 spec 与成品
└── index.sqlite                     # 可 100% 重建的索引（可删）
```

- 软件只读写这个文件夹，**不建云、不做同步、不私自创建目录**。
- 多设备同步用 Syncthing / WebDAV / Git——它们本来就为这件事设计。
- 删掉 `index.sqlite` 不丢任何数据。

## 怎么按岗位（JD）改简历

1. 选目标岗位与职级（内置 **60 类**岗位画像，细分行业 + 职级）
2. 回答裁剪问卷（系统会追问关键取舍）
3. 生成裁剪策略：保留 / 压缩 / 删除 + 理由 + ATS 关键词
4. 选模板（**10 套**：ATS 单列 / 学术 CV / 教师 / 创意 / 商务 / 技术紧凑 / 优雅衬线 / 极简等）并预览
5. 导出 PDF / DOCX（ATS 单列）/ Markdown

原素材不动，改动只发生在这一次导出里，可随时回到库内重渲染。

## 导出与 ATS

| 格式 | 用途 | 说明 |
|---|---|---|
| DOCX | ATS / 国内 HR 系统 | 单列、无文本框，字段可解析 |
| PDF | 投递 / 打印 | 桌面 Typst 渲染，全平台 DartPdf 兜底；**保留文本层**，可选中、可被解析 |
| Markdown | 版本对比 | 可放进 Git，改动可 diff |

固定页数是硬约束：先渲染计量页数 → 按取舍权重确定性裁剪 → 重渲染（≤8 轮），不是按比例乱删。

## 常见问题

**Q：怎么把以前做过的事整理成一份简历？**
一次录入、长期累积：每条经历一个记录文件，软件自动编译成完整简历；新增一条立刻重编译。

**Q：简历数据能存在自己电脑的文件夹里吗？**
能，且这是唯一存储方式。纯文本 JSON/YAML + 附件，可 diff、可 Git。

**Q：有没有不上传云端、不注册账号的简历软件？**
有。不上传、不建账号；除 Web 演示版外可完全离线。AI 可接本地 Ollama 或自带 Key。

**Q：每次投不同岗位都要重新改一遍，怎么办？**
用裁剪问卷生成这一版的取舍策略，原素材不动；同一份库可反复出不同版本。

**Q：能导出 DOCX 给 ATS 用吗？**
能，单列 ATS 友好；同时支持 PDF 与 Markdown。

**Q：学术 CV 和求职简历能共用数据吗？**
能，论文/项目/教学经历存在同一份库，按模板与筛选条件分别导出。

**Q：是开源软件吗？**
源码公开，但许可是 PolyForm Noncommercial 1.0.0（非 OSI 开源许可），商业用途需授权。
